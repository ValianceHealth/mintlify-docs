## What the API is for

Healthproximate offers programmatic access for customers and approved implementation
partners who want to integrate the platform into their own systems — for example, to
code clinical text, group DRGs or price procedures from another application.

This page is a **high-level overview**. The endpoint-by-endpoint contract lives in
the [API Reference](/api/authentication) tab.

<Info>
  **What is published, and what is not.** The API Reference documents the
  endpoints a customer key can actually call — an explicit, curated list. The
  **complete** internal schema, including administrative and internal-only
  endpoints, is not published here and remains available only through controlled
  access channels to approved customers and partners.

  An endpoint appears in the reference because someone chose to publish it, never
  because it exists. So the reference is narrower than the platform on purpose.
</Info>

## How access works

- **Programmatic access is granted per organization.** Users with API access can
  create and revoke keys themselves under **Settings → API → Keys**; otherwise,
  request access from the Valiance Health team.
- Every key starts with `hpx_`. Send it either way — both are accepted:
  - `X-API-Key: hpx_...`
  - `Authorization: Bearer hpx_...` (what OpenAI-compatible SDKs send)
- A key can be narrowed with **scopes**. See [Authentication](/api/authentication).
- All requests use **HTTPS**, and all results are **scoped to your organization**.

<Warning>
  Treat API keys as secrets. Never commit them to version control, never share
  them publicly, and store them in environment variables or a secrets manager.
  Revoke a key under **Settings → API → Keys** if you believe it leaked.
</Warning>

## What you can build

- **Clinical coding** — map clinical text to ICD-10-CM, ICD-10-PCS, SNOMED CT or
  RxNorm concepts. See [Diagnosis coding](/api/coding/diagnosis).
- **DRG grouping** — classify an encounter, one at a time or in batches.
- **PHI-safe LLM gateway** — OpenAI-compatible chat completions with redaction
  before any model sees the request. See [Models](/api/models).
- **Price predictions** — see [Pricing in your app](/api/pricing/in-your-app).
- **FHIR R4** — terminology operations, `$classify-drg` and `$autocode`. See
  [EHR integration](/api/fhir/ehr-integration).
- **MCP** — connect an AI assistant to Healthproximate tools. See [MCP](/api/mcp).

### Example: code a diagnosis

```bash
curl -X POST https://api.v2.healthproximate.com/api/v1/search/ \
  -H "X-API-Key: hpx_..." \
  -H "Content-Type: application/json" \
  -d '{"query": "community acquired pneumonia", "domain_id": "Condition", "vocabularies": ["ICD10CM"], "top_k": 5}'
```

## Conventions

- **HTTPS only.**
- **JSON** request and response bodies for application endpoints.
- **Snake_case** field names in request and response payloads.
- Every response carries an `X-Request-Id`; include it in support requests.

## Rate limits

Limits are **per key**, with separate budgets per endpoint class. A **429** carries
`Retry-After` and `X-RateLimit-*` headers. See [Errors and limits](/api/errors-and-limits).
