The gateway serves models from five providers. Every model runs under a signed BAA — AWS or Microsoft. Whatever model you pick, the redaction path is identical: identifiers never reach the model.

**Where each model processes your data is covered by our PDPA Transfer Impact Assessment**, which names every destination. We share it under NDA — ask us, and ask before you build against a model if residency is a requirement for you. Your contract then sets which models your organization may call, and anything outside that clearance returns `403` with `code: "model_not_allowed"`.

If you omit `model`, the gateway uses `apac.amazon.nova-pro-v1:0`.

Every model in this catalog supports [tool calling](/api/tool-calling). Models without tool support are not listed.

## Choosing a model

```bash
curl https://api.v2.healthproximate.com/api/v1/llm/chat/completions \
  -H "Authorization: Bearer hpx_..." \
  -H "Content-Type: application/json" \
  -d '{
    "model": "apac.amazon.nova-pro-v1:0",
    "messages": [{"role": "user", "content": "Summarize this discharge note: ..."}]
  }'
```

<Info>
  **Per-organization clearance.** Your contract sets the menu. Models outside your clearance return `403` with `code: "model_not_allowed"`. There is no region or routing parameter on the request — the model you name determines how it is served, so your clearance is what guarantees the arrangement rather than a per-call flag we would have to trust the caller to set.
</Info>

## Errors you may see

| Status | Code | Meaning |
| --- | --- | --- |
| `403` | `model_not_allowed` | The model is outside your organization's clearance. Pick a model from your cleared set. |
| `503` | — | The redaction engine is unavailable. The gateway fails closed rather than forward un-redacted text. |

See [Errors & limits](/api/errors-and-limits) for the full error contract.
