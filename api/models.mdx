The gateway serves models from five providers. Every destination is **named** below, and inference runs under our signed BAAs (AWS and Microsoft Azure). Whatever model you pick, the redaction path is identical — identifiers never reach the model.

**Read the residency column before you choose.** Only the Amazon Nova family is bounded to APAC and carries a completed transfer assessment. Every other model on this page can process outside the region you might assume, and its transfer assessment is still open. If your contract requires APAC-resident processing, ask us to restrict your clearance to the Nova family.

If you omit `model`, the gateway uses `apac.amazon.nova-pro-v1:0`.

Every model in this catalog supports [tool calling](/api/tool-calling). Models without tool support are not listed.

## Amazon

| Model ID | Tier | Residency | Transfer assessment |
| --- | --- | --- | --- |
| `apac.amazon.nova-pro-v1:0` | Standard (default) | APAC-bounded, 10 named `ap-*` regions | Complete |
| `apac.amazon.nova-lite-v1:0` | Light | APAC-bounded, 10 named `ap-*` regions | Complete |
| `apac.amazon.nova-micro-v1:0` | Micro | APAC-bounded, 10 named `ap-*` regions | Complete |

Bedrock `apac` inference profiles. The routing set was verified from `ap-southeast-5` with `aws bedrock get-inference-profile`, and is these ten regions and no others:

`ap-southeast-1`, `ap-southeast-2`, `ap-southeast-3`, `ap-southeast-4`, `ap-southeast-5`, `ap-northeast-1`, `ap-northeast-2`, `ap-northeast-3`, `ap-south-1`, `ap-south-2`.

No US. No EU.

<Note>
  **APAC-bounded is not Malaysia-only.** Requests enter AWS in Malaysia (`ap-southeast-5`), but the inference profile may serve any of the ten regions above, and we do not control or observe which. AWS offers no single-region option for these models: every foundation model in `ap-southeast-5` is inference-profile-only, and the only Nova profiles there are the `apac.*` ones. In-country-only processing needs a different arrangement — ask us if your contract requires it.
</Note>

## Anthropic

| Model ID | Tier | Residency | Transfer assessment |
| --- | --- | --- | --- |
| `global.anthropic.claude-opus-5` | Frontier (most capable) | **Global — may include the US** | Open |
| `global.anthropic.claude-sonnet-5` | Frontier | **Global — may include the US** | Open |
| `global.anthropic.claude-haiku-4-5-20251001-v1:0` | Fast | **Global — may include the US** | Open |

These are `global.*` inference profiles on AWS Bedrock, under the AWS BAA. AWS describes the profile as routing "globally across all supported AWS Regions", and its model list carries a region-less ARN — so the destination is not bounded to any region or continent.

Use the Nova family instead if you need an APAC-bounded destination.

The open-weight `gpt-oss` models run on AWS Bedrock in Tokyo. That is a cross-border transfer from Malaysia, though it stays within APAC.

## Choosing a model

```bash
curl https://api.v2.healthproximate.com/api/v1/llm/chat/completions \
  -H "Authorization: Bearer hpx_..." \
  -H "Content-Type: application/json" \
  -d '{
    "model": "apac.amazon.nova-pro-v1:0",
    "messages": [{"role": "user", "content": "Summarize this discharge note: ..."}]
  }'
```

<Info>
  **Per-organization clearance.** Your contract can restrict the menu — for example, APAC-resident models only. In that case, models outside your clearance return `403` with `code: "model_not_allowed"`.
</Info>

## Errors you may see

| Status | Code | Meaning |
| --- | --- | --- |
| `403` | `model_not_allowed` | The model is outside your organization's clearance. Pick a model from your cleared set. |
| `503` | — | The redaction engine is unavailable. The gateway fails closed rather than forward un-redacted text. |

See [Errors & limits](/api/errors-and-limits) for the full error contract.
