The gateway serves models from five providers. Every model runs under a signed BAA — AWS or Microsoft — and every destination is named below. Whatever model you pick, the redaction path is identical: identifiers never reach the model.

**You choose your destination by choosing your model.** Each table below names the processor (who handles the data, under which agreement) and the destination (which regions may actually process it). If your contract requires APAC-resident processing, we restrict your organization's clearance to models that meet it, and anything outside returns `403` with `code: "model_not_allowed"`. Ask us and we will set it.

If you omit `model`, the gateway uses `apac.amazon.nova-pro-v1:0`.

Every model in this catalog supports [tool calling](/api/tool-calling). Models without tool support are not listed.

## Amazon

| Model ID | Tier | Processor | Destination | Transfer assessment |
| --- | --- | --- | --- | --- |
| `apac.amazon.nova-pro-v1:0` | Standard (default) | AWS Bedrock — BAA, HIPAA-aligned | APAC-bounded — 10 named `ap-*` regions | Complete |
| `apac.amazon.nova-lite-v1:0` | Light | AWS Bedrock — BAA, HIPAA-aligned | APAC-bounded — 10 named `ap-*` regions | Complete |
| `apac.amazon.nova-micro-v1:0` | Micro | AWS Bedrock — BAA, HIPAA-aligned | APAC-bounded — 10 named `ap-*` regions | Complete |

Bedrock `apac` inference profiles. The routing set was verified from `ap-southeast-5` with `aws bedrock get-inference-profile`, and is these ten regions and no others:

`ap-southeast-1`, `ap-southeast-2`, `ap-southeast-3`, `ap-southeast-4`, `ap-southeast-5`, `ap-northeast-1`, `ap-northeast-2`, `ap-northeast-3`, `ap-south-1`, `ap-south-2`.

No US. No EU.

<Note>
  **APAC-bounded is not Malaysia-only.** Your requests enter AWS in Malaysia (`ap-southeast-5`) — that is our account and our entry region. The inference profile may then serve any of the ten regions above. AWS offers no single-region option for these models: every foundation model in `ap-southeast-5` is inference-profile-only, and the only Nova profiles there are the `apac.*` ones. If your contract requires in-country-only processing, tell us — it needs a different arrangement, and we would rather scope it than have you assume it.
</Note>

## Choosing a model

```bash
curl https://api.v2.healthproximate.com/api/v1/llm/chat/completions \
  -H "Authorization: Bearer hpx_..." \
  -H "Content-Type: application/json" \
  -d '{
    "model": "apac.amazon.nova-pro-v1:0",
    "messages": [{"role": "user", "content": "Summarize this discharge note: ..."}]
  }'
```

<Info>
  **Per-organization clearance.** Your contract sets the menu — for example, APAC-resident destinations only. Models outside your clearance return `403` with `code: "model_not_allowed"`. There is no region parameter on the request: the destination follows the model you name, so the clearance is what guarantees it rather than a per-call flag we would have to trust the caller to set.
</Info>

## Errors you may see

| Status | Code | Meaning |
| --- | --- | --- |
| `403` | `model_not_allowed` | The model is outside your organization's clearance. Pick a model from your cleared set. |
| `503` | — | The redaction engine is unavailable. The gateway fails closed rather than forward un-redacted text. |

See [Errors & limits](/api/errors-and-limits) for the full error contract.
